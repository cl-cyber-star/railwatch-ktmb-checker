# Railwatch KTMB checker

Railwatch is a five-minute KTMB ordinary-seat checker with user-owned journey
monitors, browser and mobile push alerts, and a Chrome/Edge session connector.

Each Railwatch user connects their own KTMB account from the official KTMB
website. The extension never reads or sends the KTMB password. It captures only
KTMB cookies and KTMB local storage after login, then exchanges them for a
short-lived one-use code generated by the signed-in Railwatch dashboard. The
hosted backend encrypts that session and associates it with the correct
Railwatch user.

## Architecture

```text
Supabase Cron (every five minutes)
  → GitHub workflow_dispatch
    → Python/Playwright worker
      → hosted Railwatch checker API
        → one isolated KTMB browser context per connected user
          → monitor results, session rotation, and owner-specific push alerts
```

Supabase Cron is the sole scheduler. The GitHub workflow intentionally exposes
only `workflow_dispatch`; do not add a second GitHub `schedule` block.

## User KTMB connection

The unpacked Manifest V3 extension is in [`extension/`](extension/).

1. Sign in to Railwatch with ChatGPT.
2. Select **Connect KTMB** and download the connector package.
3. Unzip it and open `chrome://extensions` or `edge://extensions`.
4. Enable **Developer mode**, select **Load unpacked**, and choose the extension
   folder.
5. Sign in on `https://online.ktmb.com.my/` using the user's own KTMB account.
6. Generate a one-use code in Railwatch and paste it into the extension.

Connector codes expire after 10 minutes and can be used once. The hosted app
stores only AES-256-GCM-encrypted browser state. The checker decrypts it only in
memory for that user's isolated browser context.

If KTMB ends a session, Railwatch marks only that account as
`reauth_required`, pauses its checks, records one activity item, and sends that
user a reconnect push notification. Other users continue normally.

## Reliability behavior

- One browser context and encrypted session per Railwatch user.
- Optimistic session versioning prevents an older run overwriting a newer
  session.
- One automatic retry for temporary Playwright interaction failures.
- Visible train rows and visible **Pick Seats** controls only.
- Scroll-before-click, DOM-click fallback, and modal-open verification.
- Per-monitor errors are posted without presenting zero seats as a successful
  result.
- GitHub concurrency prevents overlapping checker runs.
- The scheduled job uses the pinned Playwright image, so Chromium and its OS
  dependencies are already present instead of being installed every run.

## Seat rules

Railwatch counts only selectable Standard/ordinary seats. Business, premium,
VIP, OKU/accessibility-reserved, sold, blocked, and non-selectable seats are
excluded. Departure windows are inclusive and same-day.

## Python worker

The worker requires Python 3.12. Install locally:

```powershell
py -3.12 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pip install --no-deps -e .
python -m playwright install chromium
```

Required environment values:

| Variable | Purpose |
| --- | --- |
| `RAILWATCH_API_URL` | Hosted Railwatch backend URL |
| `RAILWATCH_CHECKER_SECRET` | Checker API bearer secret and session-encryption key material |
| `OAI_SITES_AUTHORIZATION` | Hosted Sites authorization value |

Optional values:

| Variable | Default |
| --- | --- |
| `RAILWATCH_SESSION_API_PATH` | `/api/checker/session` |
| `RAILWATCH_HTTP_TIMEOUT_SECONDS` | `30` |

`KTMB_STORAGE_STATE_B64` is no longer required by the scheduled checker. The
legacy `capture-session` command remains available only as a local diagnostic;
normal users connect through the Chrome/Edge extension.

Validate and run locally:

```powershell
python -m railwatch doctor
python -m ruff check .
python -m mypy
python -m pytest -v
python -m railwatch check
```

The last command contacts the hosted Railwatch API and KTMB and posts real
monitor results.

## Streamlit operator dashboard

`streamlit_app.py` is an operator-only view over the checker API. It lists
active monitors and displays only aggregate KTMB account health; it never shows
cookies, encrypted states, link codes, or user email addresses.

```powershell
python -m pip install -r requirements-frontend.txt
python -m pip install --no-deps -e .
python -m streamlit run streamlit_app.py
```

Do not expose the Streamlit server publicly because it holds checker
credentials. User sign-in, monitor ownership, account connection, and push
subscriptions belong to the hosted Railwatch app.

## GitHub workflow

The scheduled workflow runs in
`mcr.microsoft.com/playwright/python:v1.55.0-noble`, installs only the pinned
Python packages and this project, validates configuration, and performs one
checker cycle. Supabase calls the workflow-dispatch API every five minutes.

Keep the three required values under **Settings → Secrets and variables →
Actions**. No KTMB account session belongs in GitHub Secrets after all users
have connected through Railwatch.

## Troubleshooting

- **Reconnect required:** open Railwatch on desktop, select **Reconnect**, sign
  in on official KTMB, and use a new one-use code.
- **One monitor interaction failed:** the worker retries once and records the
  remaining error in Railwatch activity; the next five-minute run proceeds.
- **No automatic run:** verify the Supabase Cron job is active and that it calls
  the `railwatch.yml` workflow on `main`.
- **Duplicate runs:** keep `workflow_dispatch` and remove any GitHub `schedule`
  block; Supabase is the only scheduler.
- **KTMB page changed:** inspect the first actionable Playwright error and update
  the smallest affected selector or modal assertion.
